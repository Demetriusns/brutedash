# Project Orion — dev log

## 2026-10-02
- **Phase 3.5 batch 3 — per-device behavior profiles (quiet-first: know what's normal, only shout when a device acts unlike itself).** The monitor now learns each device's habits: a `device_profiles` table stores per-MAC, per-hour baselines (average bytes moved and average outside contacts per local hour) learned from 14 days of flows, attributed to hardware addresses via ARP sightings and rebuilt lazily when stale (>6h). New `behavior_deviation` rule (Medium, plain-English fields): fires only when a device moves >=4x its own baseline for the current hour AND clears a 250 MB absolute floor, requires 3+ days behind that baseline hour, skips devices under 24h old (probation watch covers those), 24h cooldown per device. Dashboard devices page gains a "Normal for this device" column ("~90 MB/hr · busiest 6-7am · learned over 5d") from /api/devices profile summaries; devices with <3 days of history show "Still learning". Tested against a scratch DB: 5-day baseline learned, spike fires with the friendly name in the title, sub-250MB burst stays quiet, probation device ignored, cooldown prevents re-fire on second run; `node --check` clean. The cooldown LIKE-match needed the MAC in the alert detail (renamed devices hid it) — fixed before commit.
